# Code review: Netlify install failure (better-sqlite3)

- Owner: eng-code-review
- Status: draft
- Date: 2026-09-25
- Change: working tree on branch `redesign` after commit bc98ac6 (6 files: `nuxt.config.ts`, `package.json`, `bun.lock`, `tests/build/static.spec.ts`, `tests/fixture-site/static.spec.ts`, `tests/fixture-site/collections.spec.ts`)
- Intent: the first Netlify branch deploy of `redesign` failed at "Install dependencies": `node-gyp rebuild` in `node_modules/better-sqlite3` crashed with `TypeError: LRU is not a constructor` (Node 24.21.0, Linux x64, bun 1.3.12).
- Checks run (2026-09-25): a clean `bun install --frozen-lockfile` installs 1,067 packages with no `better-sqlite3` and no native compilation; `bun run generate` exit 0 with `.data` removed first (the content database is written through `node:sqlite`); `bun run lint` exit 0; `bun run typecheck` exit 0; `bun run test` exit 0 (79 unit, 157 browser, 3 skipped); `bun run test:slow` 5 passed

## Root cause

`better-sqlite3` 13.0.3 has no install script but ships a `binding.gyp`, so the package manager runs an implicit `node-gyp rebuild` on install; bun runs it because the package is on its default trusted list. On the Netlify image that rebuild failed (node-gyp's `semver` resolved an incompatible `lru-cache`). Locally the same step succeeded, which hid the problem. The package was only needed by two things:
- **Nuxt Content:** it falls back to `better-sqlite3` for its build-time database when no connector is set.
- **The tests:** three test files opened the database with it.

An empty `trustedDependencies` did not stop the implicit rebuild with bun 1.2.21 (tried, reverted).

## Summary

The dependency is gone:
- **Build:** Nuxt Content uses Node's built-in SQLite (`experimental.sqliteConnector: "native"`, Node ≥ 22.5; the site builds on Node 24).
- **Tests:** they open the database with `node:sqlite`.
- **Lockfile:** `better-sqlite3` and its type package left `package.json`. The lockfile was regenerated by `bun install`, because the old one kept `better-sqlite3` as a resolved optional peer of `@nuxt/content` and `db0`.

The regeneration also moved four transitive development-tool packages: `@devframes/agentic` and `devframe` 1.0.0 → 1.1.0, `engine.io-client` 6.6.6 → 6.6.7, and `socket.io-client`. Every direct dependency stays pinned. Verdict: approve with changes (one low finding).
